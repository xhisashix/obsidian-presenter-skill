# Obsidian Presenter コンサルティング・デザインパターン集 (Design Patterns)

Obsidian Presenter v1.6+ の「スライド・テンプレート・ナビゲーター」に搭載されている**デザイン絶対原則（6原則）**、**12の伝達目的マッピング**、および**全13種のコンサルティング・スライドテンプレート＋スマートレイアウト**の完全リファレンスです。

---

## 1. コンサルティング・スライドデザインの6大原則

スライドを設計・推敲する際は、常に以下の6原則を遵守してください。

1. **🎨 黄金の配色比率（70：25：5の法則）**:
   - **ベースカラー（70%）**: 背景や余白（`#ffffff` 等）で視覚ノイズを抑える。
   - **メインカラー（25%）**: 見出しや本文、標準カード枠（`#1e293b` 等）。
   - **アクセントカラー（5%）**: 最も重要な結論、ボトルネック、最優先象限（`🎯` や `[最優先]`, `[牽引]`）にのみ使用する特効薬。
2. **Aa タイポグラフィと文字量の厳格化**:
   - 文字がスライドに収まらない場合は「文字を詰め込む」のではなく「スライドを2枚に分割する（`---` で見出し自動継承 `1-1, 1-2`）」または「詳細を `> [!note]` へ逃がす」。
3. **📐 ホワイトスペースと整列の原則**:
   - 並列カラム（2カラム・3カラム）では、**各カラムの見出し語数と箇条書きの行数・文字量を厳密に揃える**ことで情報の等価性と秩序を担保する。
4. **🏗️ SCQAフレームワークとピラミッド原則**:
   - 常にトップダウン（結論ファースト）で構成する。導入は Situation（背景）→ Complication（課題）→ Question（問い）→ Answer（結論・解決策）で展開する。
5. **📝 アクションタイトルの義務化**:
   - スライド上部の `## H2` は単なる名詞ラベル（例: `× 導入スケジュール`）ではなく、**動詞を含む完全な結論メッセージ文**（例: `◯ 3段階の段階的ロールアウトにより、現場負荷を抑えて6ヶ月で全社移行を完了する`）にする。
6. **🎯 1スライド・1メッセージの徹底**:
   - 1枚のスライドに複数の主張を盛り込まない。聴衆が3〜5秒でスキャンできる情報量（日本語100文字程度・箇条書き3〜5行）に絞り込む。

## 2. 伝達目的から選ぶ最適レイアウト早見表（12の目的）

| 伝えたい目的・シーン | 第1推奨テンプレート | 第2推奨テンプレート |
| :--- | :--- | :--- |
| 1. ステップ・手順・時系列の変化を示したい | **パターン1: ホリゾンタル（横並び）フロー型** | パターン2: 縦並び要素＋右向きフロー型 |
| 2. 部門間の連携・複雑な業務フローを整理したい | **パターン3: スイムレーン（部門別）タイムライン型** | - |
| 3. 循環するプロセスや継続的改善を示したい | **パターン4: サイクル・循環型** | - |
| 4. 結論や方針をテキスト主体で力強く提示したい | **パターン13: エグゼクティブサマリー型** | - |
| 5. AとBの違いや、現状と未来を比較・対比したい | **パターン5: 2カラム・テキスト＆ビジュアル型** | - |
| 6. 3つの選択肢や戦略の柱を並列に提示したい | **パターン6: 3カラム・ピラー型** | - |
| 7. データから導き出したインサイト（結論）を証明したい | **パターン9: チャート主導＋インサイト抽出型** | - |
| 8. 市場でのポジショニングや要素の分類を行いたい | **パターン7: 2軸マトリクス型** | - |
| 9. 階層構造やピラミッド型の組織・概念を示したい | **パターン8: ピラミッド階層図型** | - |
| 10. 最も重要な1つのKPI（数値）を強烈に印象付けたい | **パターン10: ビッグナンバー（単一指標）型** | - |
| 11. 数値増減の要因分解や、プロセスごとの離脱率を示したい | **パターン11: ファネル分析型** | - |
| 12. 複数のKPIや情報を俯瞰的なダッシュボードで見せたい | **パターン12: 弁当箱型グリッド (Bento Box)** | - |

## 3. カテゴリ別・全13種のコンサルティング・スライドパターン

### 【A. 動的構造（ステップ・フロー）】

#### パターン 1: ホリゾンタル（横並び）フロー型 (`horizontal-flow`)
- **用途**: 明確な順序を持つ業務手順や、プロジェクトの3〜4フェーズ展開。
- **ルール**: 短期記憶の限界を考慮し3〜4ステップに絞る。最終フェーズに `🎯` や `[目標]` を置いてゴールを強調する。

```markdown
## 3段階の段階的展開プロセスにより、現場の混乱を抑えて半年で全社移行を完了する

<!-- columns 3 step -->

### Phase 1: 先行検証期（1〜2ヶ月）
- 現状業務フローの棚卸し
- パイロット部署での先行導入
- 初期KPI基準値の計測

### Phase 2: 段階展開期（3〜4ヶ月）
- 標準テンプレートの全社配布
- 部門別ハンズオン研修の実施
- 初期ボトルネックの解消

### Phase 3: 定着化期（5〜6ヶ月） 🎯
- [目標] 資料作成工数 **-65%** 達成
- 定常モニタリング運用へ移行
- 創出時間の戦略業務への再配分

<!-- /columns -->
```

#### パターン 2: 縦並び要素＋右向きフロー型 (`vertical-flow`)
- **用途**: 各ステップに対するタスク・成果物・完了基準など説明テキストが多い場合。
- **ルール**: 上部に `> [!tip]` で全体の進行フローを示し、下部の3カラムに各フェーズの詳細を揃えて配置する。

```markdown
## 各フェーズの主要タスクと完了基準を明確化し、手戻りゼロでシステム移行を完遂する

> [!tip] 全体進行フロー：Step 1（要件定義） ➔ Step 2（設計・構築） ➔ Step 3（検証・本番移行）

<!-- columns 3 card -->

### 1. 要件定義フェーズ
- [タスク] 現行業務課題の特定と要件確定
- [成果物] 業務フロー図・要件定義書
- [完了基準] ステークホルダー全員の承認

### 2. 設計・構築フェーズ
- [タスク] データ連携仕様の策定と実装
- [成果物] 外部設計書・プロトタイプ環境
- [完了基準] セキュリティ・設計レビュー通過

### 3. 検証・移行フェーズ
- [タスク] ユーザー受入テスト（UAT）と移行
- [成果物] テスト完了報告書・運用手順書
- [完了基準] 重大欠陥ゼロでの本番稼働開始

<!-- /columns -->
```

#### パターン 3: スイムレーン（部門別）タイムライン型 (`swimlane`)
- **用途**: 複数の部門やシステムが絡み合う業務フローとボトルネックの可視化。
- **ルール**: Markdownテーブルで部門×ステップを表現し、滞留箇所に `[ボトルネック]` バッジを付与して下部 Callout で改革案を示す。

```markdown
## 部門間の契約審査プロセスを統合し、承認リードタイムを5営業日から即日へ短縮する

| 担当部門 | Step 1: 案件申請（受付） | Step 2: リスク審査（確認） | Step 3: 承認・締結（完了） |
| :--- | :--- | :--- | :--- |
| **営業部門** | 顧客合意・申請起票 | 差戻し対応・条件調整 | 電子契約送付・受注登録 |
| **法務部門** | — | [ボトルネック] 全件目視チェック（平均4日滞留） | 最終承認印・台帳記録 |
| **基幹システム** | 申請データの自動取込 | 定型条項のAI自動判定 | 契約書の自動アーカイブ |

> [!important] 業務改革のポイント
> 全体の **80%** を占める標準契約は **Step 2をAI自動審査へ切り替え**、法務部門は例外リスク案件（残り20%）のみに集中させます。
```

#### パターン 4: サイクル・循環型 (`cycle`)
- **用途**: PDCAサイクル、プロダクト改善ループ、フライホイール型ビジネスモデルの説明。
- **ルール**: 上部にコア価値を示し、`<!-- columns cycle -->` で4つのステップを時計回り（右上➔、右下▼、左下◀、左上▲）に配置する（※3番目と4番目の記述順に注意：2×2グリッドの下段左側が4、下段右側が3として時計回りに繋がります）。

```markdown
## ナレッジ還流ループの確立により、組織の提案品質と意思決定速度を自律的に高める

> [!important] コア・エンジン：Markdown起点の高速ナレッジ改善フライホイール

<!-- columns cycle -->

### [1. 記録] 日常業務メモの蓄積（右上へ ➔）
- 商談議事録や企画アイデアをMarkdownで記録
- 現場の一次情報をリアルタイムに集約

### [2. 構造化] AIスキルによる即時スライド化（右下へ ▼）
- 自然言語指示から1分で提案スライドを生成
- コンサル基準のフレームワークへ自動整形

### [4. 還流] ベストプラクティスの資産化（左上へ ▲） 🎯
- [成果] 成約率 **+35%** 向上・知見をテンプレへ還流
- さらなる高速提案へ繋がる好循環を実現

### [3. 展開] HTML / PPTXでの全方位共有（左下へ ◀）
- 経営層や顧客へ単一HTML・PPTXで即座に共有
- フィードバックをその場で回収・反映

<!-- /columns -->
```

### 【B. 静的構造（比較・対比・構造）】

#### パターン 5: 2カラム・テキスト＆ビジュアル型 (`two-column`)
- **用途**: 課題と打ち手、結論と証拠（Before/After比較表や図表）の提示。
- **ルール**: 人間の視線（Z/F型）に合わせ、`<!-- columns 2 1:2 card -->` で「左に要点テキスト、右に比較テーブルや図解」を一貫させる。

```markdown
## 従来の手作業による資料作成から脱却し、単一Markdown基盤への移行で生産性を3倍に高める

<!-- columns 2 1:2 card -->

### 現状の課題と変革の方向性
- [課題] 体裁調整に週平均5時間を浪費
- [原因] メモとスライドの二重管理・分断
- [解決策] **執筆と投影を単一基盤へ完全統合**

### Before / After 構造比較

| 比較観点 | Before（従来運用） | After（新運用・導入後） |
| :--- | :--- | :--- |
| **作成プロセス** | メモからPPTへ手作業転記 | **Markdownがそのままスライド化** |
| **共有スピード** | レイアウト調整後に添付送付 | **単一HTML / PPTXを即時出力** |
| **バージョン管理** | ファイル名に日付が増殖 | **Gitによる完全な差分管理** |

<!-- /columns -->
```

#### パターン 6: 3カラム・ピラー型 (`three-column`)
- **用途**: 戦略の「3本柱」、3つの主要施策、3つの選定理由の並列提示。
- **ルール**: カラムは3つが最適。各カラムの見出し語数・箇条書き行数・定量目標のフォーマットを厳密に揃える。

```markdown
## 次期中期経営計画は「顧客拡大」「収益改善」「組織変革」の3本柱で推進する

<!-- columns 3 card -->

### 🚀 1. 顧客基盤の拡大
- [重点] エンタープライズ層の開拓強化
- 業界別ソリューションパッケージの展開
- 目標：年間新規導入 **+45%** 成長

### 💎 2. 収益構造の改善
- [重点] 高付加価値AIオプションの標準化
- オンボーディング自動化による解約抑止
- 目標：営業利益率 **25%** の達成

### 🤝 3. 組織生産性の変革
- [重点] 全社ドキュメント作成のAI駆動化
- 会議資料のMarkdown標準化と即時共有
- 目標：一人あたり生産性 **1.8倍**

<!-- /columns -->
```

#### パターン 7: 2軸マトリクス型 (`matrix`)
- **用途**: ポジショニング分析、施策の優先順位付け（効果×実現性など）。
- **ルール**: `<!-- columns matrix -->` を使用し、必ず**右上象限（2つ目の `###`）が最も望ましい最優先領域（High-High `🎯`）**になるように配置する。

```markdown
## 投資対効果と実現容易性の2軸評価により、「右上象限」のコア施策へリソースを集中する

<!-- columns matrix -->

### [高効果×低実現] 2. 中長期R&D領域（左上）
- 独自LLM基盤のフルスクラッチ開発
- 少人数の専門チームでPoC検証を継続

### [高効果×高実現] 1. 最優先投資領域（右上） 🎯
- **AIスライド生成＆ナレッジ共有基盤の全社導入**
- **今期DX予算の60%を集中配分し3ヶ月で完遂**

### [低効果×低実現] 4. 凍結・撤退領域（左下）
- レガシー社内ポータルの個別カスタマイズ
- 新規投資を凍結し段階的にリプレイス

### [低効果×高実現] 3. Quick Win領域（右下）
- 定例会議アジェンダのテンプレート統一
- 現場主導の短期改善として今月中に完了

<!-- /columns -->
```

#### パターン 8: ピラミッド階層図型 (`pyramid`)
- **用途**: 経営理念〜現場基盤の階層構造、顧客ヒエラルキー、価値の積み上げ構造。
- **ルール**: `<!-- columns pyramid -->` を使用し、`### ▲ Top`、`### ■ Middle`、`### ▬ Base` の3層で見出しと解説を記述する。

```markdown
## 強固なデータ標準化（土台）の上に自動化基盤を築き、経営意思決定の即時化を実現する

<!-- columns pyramid -->

### ▲ Top：経営意思決定の即時化（頂点価値）
- [Top: 最上位層] **エグゼクティブ・コックピット**：全社業績と現場課題をリアルタイムに把握し、意思決定リードタイムを1/3へ短縮

### ■ Middle：部門横断の業務プロセス自動化（中間層）
- [Middle: 中間層] **AIワークフロー連携**：議事録・報告書・提案スライドの生成から共有までをシームレスに自動化

### ▬ Base：全社ナレッジ・データの標準化（土台層）
- [Base: 土台層] **シングルソース・オブ・トゥルース**：全社員のドキュメントを構造化Markdownとして一元管理

<!-- /columns -->
```

### 【C. 定量分析構造（データと証拠）】

#### パターン 9: チャート主導＋インサイト抽出型 (`chart`)
- **用途**: 定量データの比較・推移から明確な戦略的インサイト（結論と打ち手）を導く場面。
- **ルール**: `<!-- columns 2 2:1 card -->` で左側に `<!-- chart -->` の水平バーチャートを配置し、右側で結論と具体的な打ち手を明記する。強調したいバーにのみ `**太字**` や `[牽引]`、`🎯` を付ける。

```markdown
## クラウドAI領域が前年比+145%と急伸し、全社売上成長の70%を牽引している

<!-- columns 2 2:1 card -->

### セグメント別売上推移（定量エビデンス）

<!-- chart -->
- 既存パッケージ事業（12億円） | 前年比 +4.5% | 42%
- 保守・導入支援事業（16億円） | 前年比 +11.2% | 58%
- **クラウドAI事業（28億円）** [牽引] | **前年比 +145% 🎯** | 100%
<!-- /chart -->

### インサイトと戦略的示唆 🎯

> [!important] 結論：成長の主軸は完全にクラウドAIへ移行
> クラウドAI事業が来期増収分の7割を単独で牽引しています。

- **成長要因**: エンタープライズ顧客の単価上昇と解約率低下（0.8%）
- **打ち手**: 来期開発・営業予算の **65%** をクラウドAI領域へ重点配分

<!-- /columns -->
```

#### パターン 10: ビッグナンバー（単一指標）型 (`big-number`)
- **用途**: プレゼン全体で最も強烈に印象付けたい単一のKPI（削減率、成長率、ROIなど）の提示。
- **ルール**: 余計な表や小見出しを排除し、`<!-- kpi -->` で巨大な数字を中央に据え、`> [!important]` で換算インパクトを補足する。詳細な内訳は次のスライドに回す。

```markdown
## 全社プレゼン資料の標準化により、資料作成工数を劇的に削減する

<!-- kpi -->
**-65% 工数削減**
<!-- /kpi -->

> [!important] 年間 24,000 時間（フルタイム換算 12.5 名分）のコア業務時間を創出
> 従来のレイアウト調整・転記作業を撤廃し、創出された時間をすべて顧客提案と企画検討へ再投資します。
```

#### パターン 11: ウォーターフォールとファネル型 (`funnel`)
- **用途**: 営業・マーケティング・採用などのフェーズ別転換率と、最大ボトルネックの特定。
- **ルール**: `<!-- columns funnel -->` を使用し、最も離脱率が高いフェーズに `[ボトルネック]` を付けて視覚的にハイライトする。

```markdown
## トライアルから本契約への転換率（20%）が最大のボトルネックであり、初期伴走支援を強化する

<!-- columns funnel -->

### 1. 認知・リード獲得：10,000件（100%）
- Webマーケティング施策により計画通り順調に推移

### 2. 商談化（SQL）：2,500件（転換率 25%）
- インサイドセールスのヒアリング基準標準化により安定

### 3. トライアル導入：500件（転換率 20%）
- [ボトルネック] **初期設定の複雑さにより80%が本番活用前に離脱**

### 4. 本契約（成約）：350件（転換率 70%） 🎯
- **テンプレート導入支援の標準化によりトライアル転換率を 20% ➔ 45% へ引き上げ**

<!-- /columns -->
```

### 【D. サマリー構造（統合と俯瞰）】

#### パターン 12: 弁当箱型グリッド・レイアウト / Bento Box (`bento`)
- **用途**: 複数のKPIダッシュボード、プロジェクト実績の包括的サマリー。
- **ルール**: 上段に `<!-- columns 2 2:1 card -->`（最大モジュール＋サブモジュール）、下段に `<!-- columns 3 card -->`（3つの小モジュール）を組み合わせ、合計5〜6モジュール以内で情報のヒエラルキーを表現する。

```markdown
## 主要KPIは全領域で計画を上回り、特にエンタープライズ領域が力強い成長を牽引している

<!-- columns 2 2:1 card -->

### [重点] 年間経常収益（ARR）：+138% 成長 🎯
- エンタープライズ顧客の大口契約が牽引し、過去最高の成長率を記録
- 平均顧客単価（ARPU）が前年比 **1.6倍** に向上
```

#### パターン 13: エグゼクティブサマリー型 (`executive`)
- **用途**: 経営陣・決裁者向けプレゼンの冒頭（または総括）で、1枚で全体像と決裁事項を把握させるスライド。
- **ルール**: 上部に `> [!important]` で1〜2行の結論メッセージを配置し、下部を `<!-- columns 3 card -->` で **1. Situation（背景・現状）**、**2. Findings（課題・発見）**、**3. Recommendation（推奨策・決裁事項）** に分割する。

```markdown

> [!important] エグゼクティブ・メッセージ
> 全社の資料作成・共有基盤を統合することで、**初期投資を4ヶ月で回収** し、年間 **1.2億円相当の工数削減** を実現します。

<!-- columns 3 card -->

### 1. Situation（背景・現状）
- 事業拡大に伴い社内会議・提案資料が急増
- 部門ごとに異なるツールで資料を個別作成
- 来期の全社生産性向上目標の達成が急務

### 2. Findings（課題・発見）
- 社員の業務時間の **18%** が資料体裁調整に消滅
- 二重管理による情報劣化で年間 **1.2億円** の機会損失
- 標準Markdown基盤への統合で7割が自動化可能と判明

### 3. Recommendation（推奨策）
- [決裁] 全社標準スライド基盤の導入承認（予算800万円）
- 来月よりパイロット展開、半年後に全社本稼働
- 創出工数を顧客開拓・コア企画業務へ再配分
```

## 4. スマートレイアウト（中扉 & ビッグステートメント）

### パターン 14: 中扉スライド（セクション区切り / `section`）
アジェンダの各パート開始時に挿入します。`## 見出し` のみを記述すると自動的に中央巨大表示になります。
```markdown
## 02. 具体的な提案ソリューションとアーキテクチャ
```

### パターン 15: ビッグステートメント（引用強調 / `quote`）
プレゼン全体で最も伝えたい強い主張やビジョンを1枚のスライドで堂々と打ち出すパターンです。
```markdown
## 私たちが提供するコアバリュー

> 「Markdownをただのメモとして終わらせない。
> 思考のアウトプットをそのまま組織を動かす発信力に変える。」
```
