# Obsidian Presenter 構文・記法リファレンス (Syntax Guide)

Obsidian Presenter（v1.6+）でスライドを作成する際に利用可能な記法、HTMLコメントディレクティブ、フロントマター、およびエクスポート仕様の完全リファレンスです。

---

## 1. スライド構造化の基本 & 見出し自動継承

Obsidian Presenter は CommonMark 準拠の標準 Markdown 階層構造をそのままスライドとして認識します。コードブロック（```` ``` ```` または `~~~`）内の見出しや水平線はスライド境界として誤認識されません。

| 要素 | 記法 | スライド種別 | スライド上の役割 |
| :--- | :--- | :--- | :--- |
| **表紙スライド** | `# 見出し` (ATX H1) または `タイトル\n===` (Setext H1) | `cover` | プレゼンテーション全体のタイトル表紙（中央揃えレイアウト） |
| **通常スライド** | `## 見出し` (ATX H2) または `段落\n---` (Setext H2) | `content` | 各スライドのタイトル（アクションタイトル）となり、自動的に改スライド |
| **スライド内見出し** | `### 見出し` (H3), `#### 見出し` (H4) | - | スライド内のサブセクション、カラム見出し、図解の各ティア見出し（改ページしない） |
| **明示的改スライド** | `---`, `***`, `___` (水平線) | `content` | 空行や非段落ブロック直後の水平線で強制的に新しいスライドを開始 |

### 表紙スライドのベストプラクティス
```markdown
# プレゼンテーションタイトル
サブタイトルやキャッチコピーをここに記述

発表者: 氏名 / 所属
日付: 2026-11-01
```

### 分割スライドの見出し自動継承・連番仕様 (`inheritHeadings`)
長文セクションを `---` で複数スライドに分割した際、どのセクションの続きかが一目でわかるよう、親の `## H2` 見出しを自動継承して連番を付与します（デフォルト有効）。
- **連番フォーマット**: 同一セクション内の複数スライドに対して `Title 1-1`, `Title 1-2`, ... `Title 1-N` の形式で自動連番化されます。
- **単一スライドの保護**: 分割されていない（1枚のみの）`## H2` スライドには連番は付きません。
- **除外ルール**: 表紙（`cover`）、中扉（`section`）、引用（`quote`）スライドは親セクションをリセットし、見出し継承の対象外となります。
- **無効化**: ノート個別に無効化する場合はフロントマターに `inheritHeadings: false` を指定します。

## 2. フロントマター設定（Frontmatter）

### ゼロ設定の原則 (Zero-configuration)
**フロントマターの記述は必須ではありません（0行で動作します）。**
プラグイン設定画面（**Settings → Presenter**）のデフォルト値が自動適用されます。ノート固有でデザインや挙動を上書きしたい項目のみを冒頭の YAML フロントマターに記述します。

```yaml
---
# 必要な項目のみ指定（未指定時はプラグイン設定のデフォルト値）
header: "2026年度 提案資料"
accentColor: "#2563eb"
fit: auto
---
```

### サポートされるフロントマターキー一覧

| キー（エイリアス） | 型 | 既定値 | 説明 |
| :--- | :--- | :--- | :--- |
| `header` | string | `""` | スライド上部に表示する固定ヘッダー文字列 |
| `footer` | string | `""` | スライド下部に表示する固定フッター文字列（ページ番号の横） |
| `accentColor` | string (HEX/RGB) | `"#2563eb"` | テーマのアクセント色（タイトル下線、バッジ、強調枠、Callout等） |
| `baseColor` (`background`) | string (HEX/RGB) | `"#ffffff"` | スライドの背景色（ベースカラー） |
| `mainColor` (`color`) | string (HEX/RGB) | `"#1e293b"` | 本文および見出しの基本文字色（メインカラー） |
| `logo` | string | `""` | Vault内の画像パス (`attachments/logo.png`) または外部URL |
| `aspectRatio` | `"16:9"` \| `"4:3"` | `"16:9"` | スライドのアスペクト比 |
| `columnStyle` | `"card"` \| `"plain"` | `"card"` | カラムレイアウトのデフォルトスタイル |
| `fit` (`presenter-fit`) | `"auto"` \| `"none"` \| bool | `true` (設定値) | はみ出したスライドを最大70%（`0.70`）まで自動縮小フィットするか |
| `smartLayouts` (`smart-layouts`) | boolean | `true` | 中扉・引用・KPIビッグナンバーの自動推論を有効にするか |
| `inheritHeadings` (`inherit-headings`) | boolean | `true` | `---` 分割スライドに親H2見出しを自動継承・連番付与（`1-1, 1-2`）するか |
| `continuationPrefix` | string | `"[続き] "` | 見出し継承時のプレフィックス設定 |
| `continuationSuffix` | string | `""` | 見出し継承時のサフィックス設定 |

## 3. マルチカラム・グリッドレイアウト (`<!-- columns ... -->`)

標準Markdownの可読性を損なわないよう、1行のHTMLコメント（`<!-- columns ... -->`）でカラム領域を定義します。GitHub や VS Code、Obsidian 通常ビューではコメントが非表示となり、自然な文書として読めます（名前空間付きの `<!-- presenter:columns ... -->` も使用可能）。

### 基本構文
```markdown
<!-- columns [カラム数] [比率] [スタイル] [バリアント] -->

### カラム1
コンテンツ

### カラム2
コンテンツ

<!-- /columns -->
```
- カラム領域内の最初の見出しレベル（通常は `### H3`）と同じレベルの見出しが出現するたびに、自動的に次のカラムへ分割されます。
- 終了コメント `<!-- /columns -->` を省略した場合は、そのスライドの末尾までカラムが継続します。

### カラム数・スタイル・非均等比率
- **均等カラム数**: `<!-- columns 2 -->`, `<!-- columns 3 -->`, `<!-- columns 4 -->`（最大4カラム）
- **スタイル種別**:
  - **`card`（既定）**: `<!-- columns 2 card -->` — 薄い背景色、枠線、角丸、内側パディングを持つカード形式。
  - **`plain`**: `<!-- columns 2 plain -->` — 背景色なし（透明）、枠線なし、パディング `0` のシンプルな段組み。
- **非均等カラム比率**:
  - `<!-- columns 2:1 -->` または `<!-- columns 2 2:1 card -->`: 左が2、右が1の黄金比（左に大型チャートや図表、右に解説・インサイトなど）
  - `<!-- columns 1:2 -->` または `<!-- columns 2 1:2 card -->`: 左が1、右が2の比率（左に要点テキスト、右に比較テーブルやビジュアルなど）
  - `<!-- columns 3:1 -->`, `<!-- columns 1:3 -->`: 3対1の非均等分割

### 見出しを使わない明示的カラム区切り (`<!-- column -->`)
見出し（`###`）を伴わない段落やリスト同士を分割したい場合は、`<!-- column -->` を挟みます。
```markdown
<!-- columns 2 plain -->
左側の任意の文章・リスト
<!-- column -->
右側の任意の文章・リスト
<!-- /columns -->
```

## 4. コンサル図解・フレームワークディレクティブ

`<!-- columns ... -->` のバリアント指定や専用コメントにより、コンサルティング資料で頻出する構造図やチャートを標準Markdownのまま描画できます。

### 1. ステップフロー (`step`)
各カラム上部に `STEP 01`, `STEP 02`... のバッジと、カラム間の `➔` 矢印コネクタを自動生成します。
```markdown
<!-- columns 3 step -->

### Phase 1: 現状分析
- 業務フローの棚卸し
- ボトルネックの特定

### Phase 2: 先行導入
- パイロット部署での試行
- 運用ルールの策定

### Phase 3: 全社展開 🎯
- [目標] 工数 **-65%** 達成
- 定常モニタリングへ移行

<!-- /columns -->
```

### 2. ピラミッド階層図 (`pyramid`)
各 `###` セクションを1階層として描画します。左側に上層（アクセントカラー・狭幅）から下層（メインカラー・広幅）へ広がる台形ピラミッドシェイプ、右側に各階層の詳細解説カードを横並びで配置します（最上位層 `idx === 0` は自動ハイライト）。
```markdown
<!-- columns pyramid -->

### ▲ Top：経営意思決定の即時化（究極価値）
- [Top: 最上位層] **リアルタイム経営ダッシュボード**：全社KPIを日次で可視化し、迅速な投資判断を実現

### ■ Middle：部門横断の業務プロセス自動化（応用層）
- [Middle: 中間層] **ワークフロー統合基盤**：営業・法務・経理間の承認プロセスを自動連携

### ▬ Base：全社マスターデータの標準化（土台層）
- [Base: 土台層] **単一データレイク**：散在していた顧客・案件データを共通スキーマへ統合

<!-- /columns -->
```

### 3. ファネル分析図 (`funnel`)
各 `###` セクションを1フェーズとして、上から下へ絞り込まれる逆台形ファネルシェイプと解説カードを描画します。`[ボトルネック]` や `🎯` を含むフェーズは自動的にアクセントカラーで強調されます。
```markdown
<!-- columns funnel -->

### 1. 認知・リード獲得：10,000件（100%）
- Web広告・セミナーからの流入は計画通り推移

### 2. 商談化（SQL）：2,500件（転換率 25%）
- インサイドセールスによるヒアリング実施

### 3. トライアル導入：500件（転換率 20%）
- [ボトルネック] **初期環境構築の複雑さにより80%が離脱**

### 4. 本契約（成約）：350件（転換率 70%） 🎯
- **オンボーディング自動化によりトライアル転換率 20% ➔ 45% へ改善**

<!-- /columns -->
```

### 4. 2軸4象限マトリクス (`matrix`)
4つの `###` セクションを `2×2` の4象限グリッドとして配置し、左縦軸・下横軸（`▲ 高 (High)` / `高 (High) ▶`）を自動描画します。右上象限（第2項目）を最優先領域（`🎯` または `[最優先]`）として配置するのが鉄則です。
```markdown
<!-- columns matrix -->

### [高効果×低実現] 2. 中長期R&D領域（左上）
- 全社AIエージェント基盤の独自開発
- 少人数チームで技術検証を継続

### [高効果×高実現] 1. 最優先投資領域（右上） 🎯
- **ドキュメント・スライド作成の標準化**
- **今期リソースの60%を集中投下**

### [低効果×低実現] 4. 凍結・撤退領域（左下）
- レガシー独自ツールの保守改修
- 新規投資を停止し段階的に廃止

### [低効果×高実現] 3. Quick Win領域（右下）
- 定例会議テンプレートの統一
- 現場主導の短期改善で今月中に完了

<!-- /columns -->
```

### 5. 循環サイクル図 (`cycle`)
4つの `###` セクションを時計回りの `2×2` ループとして配置し、中央に循環コアハブ（`↻`）と各象限間の方向矢印（`➔`, `▼`, `◀`, `▲`）を自動付与します。
```markdown
> [!important] コア・エンジン：ナレッジ還流フライホイール

<!-- columns cycle -->

### [1. 蓄積] 日常業務メモの記録（右上へ ➔）
- 議事録や企画メモをMarkdownで即時記録

### [2. 構造化] AIスキルによるスライド化（右下へ ▼）
- 自然言語指示でプレゼン資料へ自動変換

### [4. 資産化] 意思決定と知見の還流（左上へ ▲） 🎯
- [成果] 会議リードタイム **-70%** を達成し次の議論へ

### [3. 共有] HTML / PPTXでの全社展開（左下へ ◀）
- 非エンジニアや経営層へワンクリック配布

<!-- /columns -->
```

### 6. 水平バーチャート (`<!-- chart --> ... <!-- /chart -->`)
`- ラベル | 数値テキスト | パーセンテージ%` の箇条書きを水平棒グラフに変換します。太字（`**`）、強調バッジ（`[牽引]`, `[重点]`, `[重要]`, `[強調]`, `[ボトルネック]`, `[目標]`）、または `🎯` を含む行のみがアクセントカラーで塗られ、それ以外はニュートラルグレーになります。
```markdown
<!-- chart -->
- 既存オンプレミス事業（12億円） | 前年比 +4.2% | 45%
- 保守・サポート事業（18億円） | 前年比 +12.0% | 65%
- **クラウドAIソリューション（28億円）** [牽引] | **前年比 +145% 🎯** | 100%
<!-- /chart -->
```

## 5. スマートスライドレイアウト (Smart Layouts)

`smartLayouts: true`（デフォルト有効）のとき、スライドの内容に応じて自動的にレイアウトが推論されます。また、HTMLコメントで明示的に指定・上書きすることも可能です。

| レイアウト種別 | 自動推論の条件 | 明示指定ディレクティブ（エイリアス） |
| :--- | :--- | :--- |
| **中扉 (`section`)** | `## 見出し` のみで本文が存在しないスライド | `<!-- slide: section -->` (`lead`, `divider`) |
| **引用強調 (`quote`)** | 本文が通常の引用ブロック（`> ...`）のみで構成されるスライド（※Callout除く） | `<!-- slide: quote -->` (`statement`, `center`) |
| **通常本文 (`content`)** | 上記以外の通常スライド（自動推論を打ち消したい場合にも使用） | `<!-- slide: content -->` (`default`, `normal`) |
| **表紙 (`cover`)** | `# H1` で始まるスライド | `<!-- slide: cover -->` |

## 6. 視覚的ハイライト & 装飾

### 1. ラベル / バッジ記法 (`[xxx]`)
`[xxx] テキスト` の形式で記述すると、アクセントカラーが適用されたピルバッジ（`<span class="presenter-badge">xxx</span>`）として自動装飾されます。
- Markdownリンク `[text](url)`、Wikilink `[[note]]`、チェックボックス `- [ ]`、脚注 `[^1]`、コードブロック内は誤変換されません。

### 2. カラム・図解カードの自動ハイライト (`.presenter-col-highlight`)
カラムまたは図解ティアの本文・見出し内に以下のいずれかのキーワードが含まれていると、そのカラムカード全体が自動的にアクセント枠でハイライトされます：
- **対象バッジ**: `[ボトルネック]`, `[重要]`, `[強調]`, `[課題]`, `[最優先]`, `[決裁]`, `[決裁事項]`
- **対象絵文字**: `🎯`

### 3. KPIビッグナンバー (`**数値**` または `<!-- kpi -->`)
- **自動検知**: 単独行に太字の数値（例: `**+140%**`, `**-65%**`, `**3.5x**`, `**1,200社**`, `**¥4.5億**` など、単位：`%`, `倍`, `社`, `人`, `円`, `万`, `億`, `k`, `m`, `b`, `ms`, `s`, `fps`, `pt`, `pts`, `x`, `件`, `点`）を記述すると、自動的に巨大フォント（44px）のKPIカードになります。
- **明示指定**: 任意の文字列を含めて確実にビッグナンバー化したい場合は `<!-- kpi -->` で囲みます。
  ```markdown
  <!-- kpi -->
  **-65% 工数削減**
  <!-- /kpi -->
  ```

### 4. 結論Calloutサマリー
Obsidian標準のCallout記法を使って、スライド上部（エグゼクティブメッセージ）や下部（Key Takeaway）に結論ボックスを配置します。
- `> [!important]` : 最重要結論、エグゼクティブサマリー、Key Takeaway
- `> [!tip]` : 全体進行フロー、推奨事項、ヒント
- `> [!warning]` : リスク、注意点、制約事項

## 7. 発表者ノート & マルチフォーマット配布連携 (`> [!note]`)

スライド内に `> [!note]`（または `> [!notes]`, `> [!speaker-note]`）を記述すると、スライド本体から自動的に分離され、以下の4つの場面で機能します：

1. **プレゼンテーション本番画面**:
   - スライドの大画面からは自動的に非表示。
   - `N` キーまたはツールバーの「ノート」ボタンで下部ドロワーに手元カンペとして展開。
2. **単一HTMLエクスポート (`Presenter: Export presentation as standalone HTML`)**:
   - ブラウザ上で「🖥 スライド表示」と「📄 配布資料（ハンドアウト）表示」をワンクリック切り替え。
   - 配布資料表示では、左側に**階層目次（TOC）サイドバー**が表示され、各スライド直下に `> [!note]` の内容が詳細解説として完全展開されます。
   - `G` / `O` キーで全スライドのサムネイル一覧グリッドを開き、任意のスライドへ即時ジャンプ可能。
3. **PowerPoint (`.pptx`) エクスポート (`Presenter: Export presentation as powerpoint (.pptx)`)**:
   - スライド本体は編集可能なネイティブシェイプ・テキスト・表として出力され、`> [!note]` の内容は各スライドのネイティブ「発表者ノート（Speaker Notes）」に自動格納されます。
4. **ハンドアウト印刷 (`Print handout with notes`)**:
   - A4用紙1枚につき「上部：スライドカード ＋ 下部：詳細解説」の報告書（SlideDoc）レイアウトでPDF出力できます。
