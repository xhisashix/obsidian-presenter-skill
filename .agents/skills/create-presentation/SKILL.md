# Create Presentation Skill

このスキルは、Obsidian Presenter プラグイン（`markdown-presenter` v1.6+）の最新仕様・記法およびコンサルティングファーム基準のスライド設計原則に完全準拠した、美しく説得力のあるプレゼンテーション資料（Markdownノート）を作成・構造化・変換するためのガイドラインです。

---

## ワークフロー (Workflow)

```
[Phase 1: 要件・目的の整理]
       ↓
[Phase 2: ストーリーライン (SCQA) & スライド構成の設計]
       ↓
[Phase 3: スライド執筆 (アクションタイトル & Presenter記法)]
       ↓
[Phase 4: デザイン6原則・はみ出し防止 & 発表者ノート推敲]
       ↓
[Phase 5: プレビュー・プレゼン・エクスポート案内 (HTML / PPTX / PDF)]
```

---

### Phase 1: 要件・目的の整理

ユーザーの入力内容に応じて、新規作成か既存ドキュメントの変換かを判断し、以下の前提を確認します。

1. **プレゼンテーションの種別・目的**:
   - 企画書・事業提案（課題解決、ROI、ロードマップ）
   - 経営報告・エグゼクティブブリーフィング（結論ファースト、KPI、意思決定事項）
   - 技術発表・勉強会・LT（コード例、アーキテクチャ図、Tips）
   - 定例・進捗報告（KPI推移、進捗ステータス、ボトルネックと対策）
2. **ターゲット読者 / オーディエンス**:
   - 経営陣・決裁者 / クライアント / エンジニア / 非エンジニア全般
3. **発表時間・想定スライド枚数**:
   - 5分LT（5〜8枚程度） / 15分〜30分（10〜20枚程度）
4. **デザインテーマ・配色（70:25:5の法則）**:
   - ベースカラー（背景 70%）、メインカラー（文字・見出し 25%）、アクセントカラー（強調 5%: 青 `#2563eb`, 水色 `#38bdf8`, 緑 `#10b981`, 橙 `#f59e0b`, 赤 `#e11d48` など）

> [!TIP]
> 既存のメモや議事録・仕様書が与えられている場合は、単なるコピペではなく「結論ファースト（ピラミッド原則）」で要約・再構造化しながらスライド化を進めます。

---

### Phase 2: ストーリーライン (SCQA) & スライド構成の設計

いきなり本文を書く前に、全体の論理構成と各スライドのレイアウト型を設計します。

1. **SCQAフレームワークによる導入設計**:
   - **S (Situation)**: 誰もが同意する現状・背景
   - **C (Complication)**: そこに生じた変化・放置できない課題・ボトルネック
   - **Q (Question)**: 解決すべき中心的な問い
   - **A (Answer)**: 提案する結論・ソリューション（エグゼクティブサマリー）
2. **アクションタイトルの義務化**:
   - 各スライドの見出し（`## H2`）は単なるトピック名（例: `× 売上推移`、`× 今後の課題`）ではなく、**動詞を含む完全な結論メッセージ文**（例: `◯ 成長領域が前年比+140%と急伸し、全社増収分の65%を牽引している`）にします。
   - **検証基準**: スライド本文を見ずに `## H2` のタイトルだけを最初から最後まで順に読んでも、プレゼンのストーリーが完全に通じるように設計します。
3. **伝達目的に応じた13種のスライドレイアウト選択**:
   - **表紙 (`# H1`)**: タイトル、サブタイトル、発表者名、日付
   - **エグゼクティブサマリー**: 上部に1行結論 Callout ＋ 下部3カラム（`Situation` / `Findings` / `Recommendation`）
   - **アジェンダ / ステップフロー**: `<!-- columns 3 step -->` によるフェーズ展開（`STEP 01` ➔ `STEP 02` ➔ `STEP 03`）
   - **各パートの中扉 (`section`)**: `## 見出し` のみのシンプルな章扉スライド
   - **構造・フレームワーク図解**:
     - **2カラム対比 (`1:2` / `2:1`)**: 左に課題・要点テキスト、右にBefore/After比較表や構成図
     - **3カラム・ピラー**: 戦略の3本柱（各列の行数・文字量を厳密に揃える）
     - **2軸4象限マトリクス**: `<!-- columns matrix -->`（右上象限を最優先領域 `🎯` として強調）
     - **ピラミッド階層図**: `<!-- columns pyramid -->`（Top / Middle / Base の3層構造と右側の詳細解説）
     - **循環サイクル図**: `<!-- columns cycle -->`（時計回りの4象限ループと中央コアエンジン）
     - **部門別スイムレーン**: Markdownテーブルと `[ボトルネック]` バッジによる業務フロー整理
   - **定量データ・指標証明**:
     - **チャート主導＋インサイト**: `<!-- columns 2 2:1 card -->` の左に `<!-- chart -->` 横棒グラフ、右にインサイト Callout と打ち手
     - **ビッグナンバー**: `<!-- kpi -->` または単独行太字数値（`**-65%**`）による単一重要指標の強調
     - **ファネル分析**: `<!-- columns funnel -->` によるフェーズ別転換率とボトルネックの可視化
     - **弁当箱型グリッド (Bento Box)**: 上段 `2:1` カラム＋下段 `3` カラムを組み合わせたKPIダッシュボード
   - **ビッグステートメント (`quote`)**: 引用ブロック（`> ...`）のみのスライドで核心メッセージを強調

### Phase 3: スライド執筆 (Presenter記法の適用)

Obsidian Presenter の最新仕様に従ってMarkdownを作成します。詳細な記法リファレンスは [references/syntax-guide.md](./references/syntax-guide.md) および [references/design-patterns.md](./references/design-patterns.md) を参照してください。

#### 1. フロントマター（ゼロ設定の原則）
- 基本設定はObsidianの設定値が自動適用されるため、**上書きしたい項目のみを最小限**記述します（フロントマター0行でも動作します）。
- レイアウト崩れを防ぐため、`fit: auto`（はみ出し自動縮小）を付与することを推奨します。

```markdown
---
header: "2026年度 提案資料"
accentColor: "#2563eb"
fit: auto
---
```

#### 2. 見出し階層ルール & 分割スライドの見出し自動継承
- `# H1`: プレゼン全体の「表紙」スライド（中央配置）
- `## H2`: 各スライドの「アクションタイトル」（自動的に改スライド）
- `### H3`: スライド内の小見出し、カラム見出し、または図解（pyramid / funnel / matrix / cycle）の各要素見出し（改スライドしない）
- `---`: 空行で挟むことで明示的に改スライド。
  - **見出し自動継承**: 同一の `## H2` セクションを `---` で複数スライドに分割した場合、自動的に親見出しが引き継がれ `タイトル 1-1`, `タイトル 1-2` のように連番が付与されます（フロントマター `inheritHeadings: false` で無効化も可能）。

#### 3. マルチカラム & コンサル図解ディレクティブ
- **2カラム比較・左テキスト＆右ビジュアル (`1:2` / `2:1`)**:
  ```markdown
  <!-- columns 2 1:2 card -->
  ### 現状の課題と変革の方向性
  - [課題] 資料作成に月20時間を浪費
  - [解決策] **Markdown直結の単一基盤へ移行**

  ### Before / After 比較
  | 観点 | Before | After |
  | :--- | :--- | :--- |
  | **作成時間** | 平均3時間 | **即時（0分）** |
  | **共有方法** | PPTX添付 | **単一HTML / PPTX** |
  <!-- /columns -->
  ```
- **ステップフロー (`step`)**:
  ```markdown
  <!-- columns 3 step -->
  ### Phase 1: 先行検証
  - 対象部署でのPoC実施
  ### Phase 2: 本格展開
  - 全社テンプレート配布
  ### Phase 3: 定着化 🎯
  - [目標] 作成工数 **-70%** 達成
  <!-- /columns -->
  ```
- **ビジネスフレームワーク図解 (`pyramid` / `funnel` / `matrix` / `cycle`)**:
  - `<!-- columns pyramid -->`: `### ▲ Top` / `### ■ Middle` / `### ▬ Base` で台形ピラミッド図＋解説カードを生成
  - `<!-- columns funnel -->`: 各フェーズの転換率・離脱率を逆台形ファネル図で可視化
  - `<!-- columns matrix -->`: 4つの `###` 見出しを2×2の4象限マトリクス（軸ラベル付き）に配置
  - `<!-- columns cycle -->`: 4つの `###` 見出しを時計回りの循環ループ（`➔`, `▼`, `◀`, `▲` と中央ハブ `↻`）に配置
- **水平バーチャート (`chart`)**:
  ```markdown
  <!-- chart -->
  - 既存領域（12億円） | 前年比 +5% | 45%
  - **最重点クラウド領域（18億円）** [牽引] | **前年比 +140% 🎯** | 100%
  <!-- /chart -->
  ```

#### 4. 視覚的装飾 & カラム自動ハイライト
- **バッジ**: `[重要]`, `[課題]`, `[POINT]`, `[ボトルネック]`, `[最優先]`, `[決裁]`, `[牽引]` と書くだけでアクセントカラーのピルバッジに自動変換。
- **カラム・図解ティアの自動ハイライト**: カラムや図解行の内部に `[ボトルネック]`, `[重要]`, `[強調]`, `[課題]`, `[最優先]`, `[決裁]`, `[決裁事項]` または `🎯` を含めると、そのカード全体が自動的にアクセント枠（`.presenter-col-highlight`）で強調表示されます。
- **KPIビッグナンバー**: 単独行の太字数値（例: `**+140%**`, `**3.5x**`）または `<!-- kpi --> ... <!-- /kpi -->` は自動で巨大フォント化。
- **結論ボックス**: `> [!important]`, `> [!tip]`, `> [!warning]` でスライドのキーテイクアウェイを強調。

### Phase 4: デザイン6原則・はみ出し防止 & 発表者ノート推敲

1. **コンサルティング・スライドのチェックリスト**:
   - **1スライド・1メッセージ**: 聴衆が3〜5秒で意図をスキャンできるか？（目安：箇条書き3〜5行、日本語100文字程度）
   - **アクションタイトル**: `## H2` が単なるラベルではなく、結論を示す完全な文（動詞を含む）になっているか？
   - **整列の原則**: 並列カラム（`columns 2` / `columns 3`）の各列で見出しの長さと箇条書きの行数・粒度が揃っているか？
   - **視線誘導（Z/F型）**: 2カラム時は原則「左に主張・テキスト、右に証拠・図表（または左に大型チャート、右にインサイト結論）」を一貫させているか？
2. **発表者ノート 兼 詳細解説 (`> [!note]`) の活用**:
   - スライド本体には要点のみを簡潔に残し、長文の背景説明、補足データ、口頭トークスクリプトはすべて `> [!note]` に分離します。
   - **マルチユース効果**:
     - **プレゼン本番**: 大画面から自動的に隠れ、`N` キーで開閉できる発表者用カンペになります。
     - **単一HTMLエクスポート**: 「📄 配布資料モード」でスライド直下に詳細解説として展開され、左側の階層目次（TOC）サイドバーから通読できる自己完結Webレポートになります。
     - **PowerPoint (`.pptx`) エクスポート**: 各スライドのネイティブ「発表者ノート（Speaker Notes）」に自動格納されます。
     - **ハンドアウト印刷**: A4用紙1枚に「スライド ＋ 詳細解説」が並ぶSlideDoc形式でPDF出力できます。

### Phase 5: プレビュー・操作・エクスポートの案内

スライドMarkdownを提示した後、ユーザーに対して以下の利用手順・Tipsを添えて案内します。

1. **リアルタイムプレビュー & テンプレート挿入**:
   - エディタ右上の **「TV」アイコン** または `Presenter: Open slide preview` でエディタ横にリアルタイムプレビューを表示。
   - 追加スライドを挿入したい場合は、プレビュー上部の **テンプレートアイコン** または `Presenter: Open slide template navigator...` から13種のコンサルレイアウトをワンクリック挿入可能。
   - はみ出し確認はツールバーの `⚠` バッジまたは `Presenter: Check slide overflow` で検査・ワンクリック分割可能。
2. **プレゼンテーション本番**:
   - 左リボンのプロジェクターアイコン、またはプレビュー上部の「開始」ボタンで全画面プレゼンを開始。
   - **操作ショートカット**:
     - `Space` / `→` / `J` / `L` : 次のスライド（`←` / `H` / `K` : 前のスライド）
     - `N` : 発表者ノートの開閉
     - `G` / `O` : 全スライド一覧グリッド（Q&A時の即時ジャンプ用）
     - `P` : 印刷・エクスポートメニュー
     - `画像・Mermaid図クリック` : Lightboxフルスクリーン拡大（`Escape` で閉じる）
3. **資料配布・エクスポート・共有**:
   - **単一HTML出力（ブラウザ閲覧用）**: `Presenter: Export presentation as standalone HTML` でObsidian不要の単一HTMLを生成。受取手は「🖥 スライド表示」と「📄 配布資料表示（階層目次サイドバー付き）」を切り替え可能（`G` キーで一覧グリッド、`#slide-N` でURL共有）。
   - **PowerPoint (`.pptx`) 出力（二次編集用）**: `Presenter: Export presentation as powerpoint (.pptx)` または印刷メニューから、編集可能なネイティブ `.pptx` ファイルを出力。
   - **PDF / ハンドアウト印刷**: ツールバーの印刷ボタンから「Print handout with notes（スライド＋解説）」または「Print slides only」を選択。
   - **テキストサマリー共有**: `Presenter: Copy summary for sharing` で、タイトル・章構成・重要結論を抽出したテキストをSlackやメール用に一発コピー。
