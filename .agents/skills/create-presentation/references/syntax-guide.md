# Obsidian Presenter 構文・記法リファレンス (Syntax Guide)

Obsidian Presenter でスライドを作成する際に利用可能な記法、ディレクティブ、フロントマターの完全リファレンスです。

---

## 1. スライド構造化の基本

Obsidian Presenter は標準Markdownの階層構造をそのままスライドとして認識します。

| 要素 | 記法 | スライド上の役割 |
| :--- | :--- | :--- |
| **表紙スライド** | `# 見出し` (H1) | プレゼンテーション全体のタイトル表紙（中央揃えレイアウト） |
| **通常スライド** | `## 見出し` (H2) | 各スライドのタイトルとなり、自動的に新しいスライドに改ページ |
| **スライド内見出し** | `### 見出し` (H3), `#### 見出し` (H4) | スライド内のサブセクションやカラム見出し（改ページしない） |
| **明示的改スライド** | `---` (3つ以上のハイフン) | 空行で挟まれた `---` で強制的に新しいスライドを開始 |

### 表紙スライドのベストプラクティス
```markdown
# プレゼンテーションタイトル
サブタイトルやキャッチコピーをここに記述

発表者: 氏名 / 所属
日付: 2026-10-26
```

## 2. フロントマター設定（Frontmatter）

### ゼロ設定の原則 (Zero-configuration)
**フロントマターの記述は必須ではありません（0行で動作します）。**
プラグイン設定画面（**Settings → Presenter**）のデフォルト値が自動適用されます。
ノート固有でデザインや設定を上書きしたい項目のみを冒頭のYAMLフロントマターに記述します。

```markdown
---
# 必要な項目のみ指定（未指定時は設定のデフォルト値）
header: "2026年度 提案資料"
accentColor: "#38bdf8"
fit: auto
---
```

### サポートされるフロントマターキー

| キー | 型 | 既定値 | 説明 |
| :--- | :--- | :--- | :--- |
| `header` | string | `""` | スライド上部に表示する固定ヘッダー文字列 |
| `footer` | string | `""` | スライド下部に表示する固定フッター文字列（ページ番号の横） |
| `accentColor` | string (HEX) | `"#2563eb"` | テーマのアクセント色（タイトル下線、バッジ、Callout等） |
| `baseColor` / `background` | string (HEX) | `"#ffffff"` | スライドの背景色 |
| `mainColor` / `color` | string (HEX) | `"#1e293b"` | 本文および見出しの文字色 |
| `aspectRatio` | `"16:9"` \| `"4:3"` | `"16:9"` | スライドのアスペクト比 |
| `columnStyle` | `"card"` \| `"plain"` | `"card"` | カラムのデフォルトスタイル |
| `fit` | `"auto"` \| `"none"` \| bool | `false` | はみ出したスライドを最大70%まで自動縮小フィットするか |
| `smartLayouts` | boolean | `true` | 中扉や引用の自動スマートレイアウトを有効にするか |
| `logo` | string | `""` | Vault内の画像パス (`attachments/logo.png`) または外部URL |

## 3. グリッドレイアウト（マルチカラム）

標準Markdownの可読性を損なわないよう、HTMLコメント（`<!-- columns ... -->`）でカラムを定義します。

### 基本構文
```markdown
<!-- columns [カラム数] [スタイル] [オプション] -->

### カラム1
コンテンツ

### カラム2
コンテンツ

<!-- /columns -->
```
※ 終了コメント `<!-- /columns -->` は省略した場合、次のスライド境界までカラムが継続します。

### カラム数
- `<!-- columns 2 -->`: 2カラム均等分割
- `<!-- columns 3 -->`: 3カラム均等分割
- `<!-- columns 4 -->`: 4カラム均等分割

### スタイル種別（Card vs Plain）
- **Card（既定）**: `<!-- columns 2 card -->`
  - 薄い背景色、枠線、角丸パディングがついたカード形式。箇条書きやポイントの強調に最適。
- **Plain**: `<!-- columns 2 plain -->`
  - 背景色なし、枠線なし、余白（gap）のみで並ぶスッキリした段組み。長めの文章や図表の並列に最適。

### 非均等カラム比率
- `<!-- columns 2:1 -->` または `<!-- columns 2:1 plain -->`: 左側が広く、右側がコンパクト（左に図や表、右に解説など）
- `<!-- columns 1:2 -->`: 左側がコンパクト、右側が広い
- `<!-- columns 3:2 -->`, `<!-- columns 2:3 -->`

### ステップフロー表示
- `<!-- columns 3 step -->` または `<!-- columns 3 step card -->`:
  - 各カラムの上部に `STEP 01`, `STEP 02`, `STEP 03` の番号バッジが自動付与され、手順やロードマップを視覚化。

### 見出しを使わないカラム区切り (`<!-- column -->`)
見出し（H3）を伴わない文章を分割したい場合は、明示的な区切りコメントを挟みます。
```markdown
<!-- columns 2 plain -->
左側の任意の文章・リスト
<!-- column -->
右側の任意の文章・リスト
<!-- /columns -->
```

## 4. スマートスライドレイアウト (Smart Layouts)

`smartLayouts: true`（デフォルト有効）のとき、スライドの内容に応じて自動的に洗練されたレイアウトが適用されます。

### 1. 中扉スライド（セクション区切り / アジェンダ）
`## 見出し` のみで本文が存在しないスライドは、自動的に文字が拡大され中央配置された「セクション区切りスライド」になります。
```markdown
## 01. 現状の課題と背景
```
※ 明示指定: `<!-- slide: section -->`

### 2. ビッグステートメント / 引用強調
スライド全体が引用ブロック（`> ...`）のみで構成されている場合、中央配置のスタイリッシュなキーメッセージスライドになります。
```markdown
## 私たちが目指す世界

> 「思考の速度でスライドを作成し、即座に対話と意思決定を行う」
```
※ 明示指定: `<!-- slide: quote -->`

## 5. 視覚的ハイライト & 装飾

### ラベル / バッジ記法
`[xxx] テキスト` の形式で記述すると、アクセントカラーが適用されたバッジとして自動装飾されます。
```markdown
- [重要] 提出期限は来週金曜日まで
- [課題] 資料作成にかかるリードタイムの削減
- [STEP 1] 要件の洗い出しと合意形成
- [POINT] Markdownとの完全な互換性を保持
```

### KPIビッグナンバー
単独の行に太字の数値を記述すると、自動的に巨大フォントのKPIカードとして描画されます。
```markdown
<!-- columns 2 card -->
### 開発工数削減
**-40%**
標準化による手戻りの防止

### リリース頻度
**3.5x**
CI/CD自動化による高速デプロイ
<!-- /columns -->
```

### 結論Calloutサマリー
Obsidian標準のCallout記法を使って、スライド下部にキーテイクアウェイを配置します。
```markdown
> [!important] Key Takeaway
> スライド作成の時間を削減することで、本来注力すべき戦略検討に集中できます。
```
- `> [!important]` : 重要結論、キーメッセージ
- `> [!tip]` : 推奨事項、ヒント
- `> [!warning]` : 注意点、リスク

## 6. 発表者ノート & 配布資料連携 (`> [!note]`)

スライド内に `> [!note]` を記述すると、以下の挙動になります：

1. **プレゼンテーション本番画面**:
   - スライドの大画面からは自動的に非表示。
   - `N` キーまたはツールバーの「ノート」ボタンで手元カンペとしていつでも確認可能。
2. **単一HTMLエクスポート (`Export as standalone HTML`)**:
   - 「スライド表示」と「配布資料（ドキュメント）表示」をワンクリックで切り替え可能。
   - 配布資料表示では、スライド直下に詳細解説として完全展開。
3. **ハンドアウト印刷 (`Print handout with notes`)**:
   - A4用紙1枚につき「スライドカード ＋ 詳細解説」の報告書レイアウトでPDF印刷可能。

```markdown
## 新規機能のアーキテクチャ

<!-- columns 2:1 plain -->
### 構成図
![[system-architecture.png]]
### 設計のポイント
- イベント駆動による疎結合化
- オフライン動作の保証
<!-- /columns -->

> [!note] 発表者用カンペ / 配布時詳細解説
> ここに背景の技術選定理由や、質疑応答で想定される質問に対する回答メモを記述します。
> スライド本番投影時は画面に表示されないため、スライド自体の文字数をすっきり保てます。
```

## 7. スライドはみ出し（Overflow）防止のベストプラクティス

スライドはプロジェクターやディスプレイ（16:9）の固定領域に描画されるため、文字が多すぎるとカード枠からはみ出してしまいます。

1. **1スライド1メッセージ**: 1枚のスライドで伝えるメッセージは原則1つに絞る。
2. **箇条書きは3〜5項目**: 1項目あたり1〜2行に収める。
3. **詳細な補足は `> [!note]` へ逃がす**: 本文を削り、解説は発表者ノートに書く。
4. **H3見出しでの分割**: 項目が多い場合は `<!-- columns 2 -->` で横並びにするか、スライドを2枚に分ける。
5. **自動フィットの活用**: フロントマターに `fit: auto` を指定することで、少し文字が多い場合でも最大70%まで自動縮小フィット可能。
